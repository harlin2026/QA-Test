# Peterson QA Lab 平台說明

> **作者**：harlin  
> **專案**：Peterson QA Lab（後台管理 + POS 收銀自動化測試平台）

## 1. 平台是什麼

**Peterson QA Lab** 是一套面向門店業務的自動化品質驗證平台，用來持續檢查兩套核心系統是否可用、是否可寫入、以及關鍵業務是否能跑通閉環：

| 系統 | 說明 | 預設地址 |
|------|------|----------|
| **後台管理（Admin）** | Peterson 後台：商品、訂單、會員、庫存、報表、系統設置等 | `http://192.168.30.55:5174` |
| **POS 收銀** | @Chill POS：點單、廚房、訂單、會員、存酒、沽清、總覽 | `http://192.168.30.55:8090` |

平台以 **Playwright** 執行瀏覽器自動化測試，並提供 **Dashboard 控制台**（`http://127.0.0.1:3456`）做可視化選擇、執行與即時日誌查看。

---

## 2. 平台解決什麼問題

傳統手工回歸往往有這些痛點：

- 發版前要點很多頁，容易漏測
- 帳號、環境、路徑一變，測試腳本難維護
- 後台與 POS 是兩套系統，跨端聯動難驗證
- 失敗時缺少即時日誌與結果彙總

本平台把回歸能力產品化：

1. **可重複執行**：同一套用例可在發版前／日常巡檢反覆跑  
2. **可視化操作**：不需要每次手打命令列  
3. **可配置**：系統地址、帳密、冒煙路徑都可在介面調整  
4. **分層覆蓋**：冒煙 → CRUD → E2E → 跨端閉環，由淺入深

## 3. 核心功能

### 3.1 測試控制台（Dashboard）

啟動：

```bash
npm run dashboard
```

主要能力：

- 左側切換 **後台管理 / POS 收銀**，以及工具選單 **AI 生成測試**
- 切換測試類型：**冒煙 / CRUD / E2E / 用戶故事 / 壓力測試**
- 單項執行、模組執行、本類型全部執行、全部執行
- **用戶故事**：由 `xuqiu/xuqiu.txt` 解析產生（`npm run xuqiu:generate`），後台對應 US-7、POS 對應 US-6；小程序 US-5 見 `xuqiu/miniapp-pending.md`
- **壓力測試**：可配置並發（預設 100 VU）、時長、爬坡；API 壓測為主，可選少量 UI 並發；支援停止
- **AI 生成測試**：用自然語言描述需求，生成 Playwright 腳本／冒煙路徑並寫入 `tests/` 與 fixture
- **即時日誌**（固定高度內捲動）
- 執行結果統計（通過 / 失敗 / 執行中 / 未跑）
- **系統配置**：修改 baseURL、登入帳號密碼（寫入 `systems.json`）
- **路徑管理**：維護冒煙／CRUD／E2E 目錄資料

### 3.2 系統配置

每個系統可獨立配置：

- 系統地址（baseURL）
- 登入帳號 / 密碼
- 顯示名稱、副標題

儲存後會更新 `systems.json`，並清除舊登入狀態，下次執行自動用新設定登入。

### 3.3 路徑與套件管理

- **冒煙**：可新增／修改頁面路徑與檢查項  
- **CRUD / E2E**：可維護套件名稱、說明、對應測試檔  

配置檔位置：

- 後台：`tests/fixtures/*.json`
- POS：`tests/pos/fixtures/*.json`
- 系統總配置：`systems.json`

### 3.4 自動登入與錯誤守衛

- 執行前自動完成 Admin / POS 登入，並保存登入態  
- 用例通過後仍會檢查：頁面錯誤彈窗、前端 pageerror、關鍵 API 失敗  
- 避免「頁面看起來開了，但其實已經報錯」的假通過  

### 3.5 跨端閉環（Admin ↔ POS）

後台與 POS 是獨立登入、獨立專案。跨端驗證透過標記橋接檔：

`test-results/e2e-bridge.json`

典型流程：

1. 後台種子商品關鍵字 → POS 驗證可見／可加購  
2. POS 種子會員手機號 → 後台會員列表可搜尋  

一鍵命令：

```bash
npm run test:e2e:bridge:product
npm run test:e2e:bridge:member
```

### 3.6 壓力測試（Admin / POS）

對後端 API（gateway：`peterson-gw.weprogram.site`）做可配置並發壓測，並可選同時跑少量 Playwright UI 並發（上限 10 workers）。

配置檔：`stress/config.json`（VU、時長、爬坡、場景路徑）

```bash
# 重新抓取頁面 API（寫入 discovered-*.json 並更新 config）
npm run stress:capture

# CLI 壓測
npm run stress -- --system=admin --vus=100 --duration=60
npm run stress -- --system=pos --vus=50 --duration=30 --with-ui --ui-workers=5
```

Dashboard：切換「壓力測試」→ 調整 VU／時長／爬坡 → 勾選場景 → 開始／停止。即時顯示 RPS、p50／p95／p99、錯誤率。

注意：

- 預設只打 **唯讀 GET**，避免 100 並發寫入污染資料  
- Token 來自 `playwright/.auth/*.json`，過期請先 `npm run login` / `login:pos`  
- 與功能測試互斥（一次一輪）；執行中可按「停止」

### 3.7 AI 生成測試

左側選單（與後台／POS 同列）點選「AI 生成測試」：選擇目標系統與類型（冒煙／CRUD／E2E）→ 填寫需求 → 生成草稿 → 預覽／微調 → 確認寫入。

寫入規則：

- 僅允許寫入 `tests/`（含 `tests/pos/`）
- 冒煙：更新 `modules.json` 路徑目錄
- CRUD／E2E：寫入 `.spec.ts` 並更新對應 fixture（`crud-modules.json` / `e2e-suites.json`）

環境變數（可選；優先使用 Dashboard「AI 配置」寫入的 `qa-data/ai-config.json`）：

| 變數 | 說明 |
|------|------|
| `AI_API_KEY` 或 `OPENAI_API_KEY` | 無配置檔時的後備 Key |
| `AI_BASE_URL` | 預設 `https://api.openai.com/v1` |
| `AI_MODEL` | 預設 `gpt-4o-mini` |

在 AI 頁點「AI 配置」可選擇廠商（GPT / DeepSeek / 千問 / Kimi / 智譜 / SiliconFlow / Ollama / 自訂），填寫 Base URL、模型與 API Key，即時寫入本機檔案，無需重啟。

## 4. 平台優點

1. **雙系統一站式覆蓋**  
   後台與 POS 共用同一套控制台，切換即可測，不用兩套工具。

2. **測試分層清晰**  
   - 冒煙：快，確認「頁面能不能開」  
   - CRUD：中，確認「資料能不能增刪查」  
   - E2E：深，確認「業務能不能串起來」  
   - 壓力：量，確認「高並發下延遲與錯誤率」  
   - AI 生成：依需求快速產出腳本草稿並納入目錄  

3. **可視化 + 可配置**  
   非開發人員也能用控制台選用例、改地址與帳密、調路徑。

4. **真實瀏覽器回歸**  
   基於 Playwright，貼近真實操作，可截圖／錄影／追蹤失敗。

5. **失敗可觀測**  
   即時日誌、結果面板、HTML Report，方便定位是哪個模組壞了。

6. **跨端業務可驗證**  
   不只測單系統，還能驗證「後台配置／資料」與「POS 前台行為」是否一致。

7. **安全可控**  
   多數 POS 結帳用例只開到支付入口；完整「支付→廚房→取餐」閉環會真實下單，請在測試門店執行，支付方式可用環境變數 `POS_PAY_METHOD`（預設現金）。

8. **易擴展**  
   新增頁面、CRUD、E2E 套件後，更新 fixture JSON 即可進控制台。

## 5. 可以進行哪些測試

目前覆蓋規模（約）：

| 系統 | 冒煙 | CRUD | E2E | 壓力 |
|------|------|------|-----|------|
| 後台管理 | 33 | 10 | 18 | API 唯讀場景（預設 100 VU） |
| POS 收銀 | 8 | 3 | 12 | API 唯讀場景（預設 100 VU） |

### 5.1 冒煙測試（Smoke）

目標：快速確認核心頁面可開啟、殼層正常、基本控件存在。

#### 後台可測模組

- 首页
- 商城设置（門店、頁面設計、小票機）
- 商品管理（分類、列表、單位、篩選模型）
- 订单管理（訂單、退貨售後）
- 会员列表
- 促销中心（優惠券）
- 积分管理
- 库存管理（查詢、出入庫、盤點、記錄）
- 存酒管理
- 报表统计（多張報表）
- 设置（模板、通知、用戶、角色、日誌）

#### POS 可測頁面

- 點單頁
- 制作进度
- 訂單列表
- 會員查詢
- 存酒列表 / 新建存酒
- 商品沽清
- 營收總覽

---

### 5.2 CRUD 測試

目標：驗證關鍵資料的新增、查詢、刪除，或至少「寫入入口」可用。

#### 後台 CRUD

- 门店管理
- 商品分类
- 筛选模型
- 商品单位
- 优惠券
- 小票机管理
- 单据模板
- 用户管理
- 角色管理
- 設定與複雜表單入口

#### POS CRUD

- 新增會員
- 新建存酒
- 購物車增刪（加購 / 清空）

---

### 5.3 E2E 閉環測試

目標：跨頁、跨模組、甚至跨系統驗證業務鏈路。

#### 後台 E2E（節選）

- 數據總覽閉環
- 商城配置閉環
- 商品目錄／上架寫入閉環
- 門店經營閉環
- 訂單與售後／訂單詳情閉環
- 會員積分促銷（讀／寫）閉環
- 庫存運營／庫存單據寫入閉環
- 存酒管理、門店出票與存酒配置閉環
- 報表巡覽閉環
- 系統管理、帳號權限生命週期閉環
- 跨端種子／驗證

#### POS E2E（節選）

- 點單到結帳入口
- 會員點單結帳閉環
- 掛單取單閉環
- 訂單與制作进度／點單到廚房交接
- 會員與存酒／存酒登記閉環
- 總覽與沽清／沽清與點單聯動
- 班次運營全鏈路閉環
- 跨端種子／驗證

---

### 5.4 建議測試場景（實際使用）

| 場景 | 建議跑什麼 | 說明 |
|------|------------|------|
| 每日巡檢 | 兩邊冒煙 | 最快確認核心頁面還活著 |
| 小版本發佈 | 冒煙 + 相關 CRUD | 針對改動模組加強 |
| 大版本／上線前 | 冒煙 + CRUD + E2E | 全量回歸 |
| 商品／會員聯動變更 | 跨端 bridge 兩條 | 驗證後台↔POS 資料一致性 |
| 收銀高峰前檢查 | POS 冒煙 + 點單／廚房／沽清 E2E | 聚焦前台營運鏈路 |

## 6. 快速開始

### 6.1 安裝依賴

```bash
npm install
npx playwright install chromium
```

### 6.2 啟動控制台

```bash
npm run dashboard
```

打開：`http://127.0.0.1:3456`

### 6.3 命令列執行（可選）

```bash
# 後台
npm run test:smoke
npm run test:crud
npm run test:e2e

# POS
npm run test:pos:smoke
npm run test:pos:crud
npm run test:pos:e2e

# 跨端
npm run test:e2e:bridge:product
npm run test:e2e:bridge:member

# 報告
npm run test:report
```


## 8. 使用注意

1. **環境可達性**：執行前請確認後台、POS 地址可訪問，帳密正確。  
2. **門店語境**：多數後台用例預設門店為「珠海门店」（可用環境變數 `E2E_STORE` 調整）。  
3. **寫入測試**：CRUD／部分 E2E 會建立臨時資料；帳號類用例會盡量清理。  
4. **支付安全**：POS 結帳相關用例預設不完成真實支付。  
5. **跨端順序**：跨端驗證套件需先跑對應「種子」再跑「驗證」，或直接用 npm bridge 腳本。  
6. **改配置後**：系統配置或帳密變更後，下次執行會重新登入。

## 9. 總結

Peterson QA Lab 的定位不是單一腳本集合，而是一套可運營的測試平台：

- **作用**：持續保障後台與 POS 的可用性與關鍵業務閉環  
- **優點**：雙系統、分層覆蓋、可視化、可配置、可觀測、可跨端  
- **能力**：冒煙、CRUD、E2E、跨端驗證，覆蓋日常巡檢到上線前全量回歸  

適合作為發版門禁、日常健康檢查，以及前後台聯動變更時的回歸工具。
